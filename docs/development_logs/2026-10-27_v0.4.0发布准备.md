## 3. 核心内容详解

### 3.1 架构与设计决策

版本与存储/操作协议版本分开：根VERSION是产品版本来源，API描述和health共用，不修改workspace user_version或operation契约。前端package及lockfile仍保留包管理器要求的字段，由CI检查一致。

portable模式仅枚举Git索引内的Markdown/TXT及根入口。指向Git文件的链接必须存在且锚点正确；未跟踪目标即使本机存在也拒绝。只有docs/local_references.json精确列明的两个本机材料目标单列，Git已跟踪文件不能被清单豁免。这样不需要上传本机SQLite、原始游戏来源或用户审计任务书。

流程：本地检查 → 发布提交 → 不含私有材料的干净克隆复核 → 分支push及真实CI → 同一发布提交的版本Tag与GitHub Release → 追加可追溯结果。main和历史分支不随发布自动合并。
