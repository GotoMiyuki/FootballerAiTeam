# M4.7：停写备份与新目录恢复

日期：2026-10-27。状态：**M4.7分项已交付；M4整体未通过，下一项M4.8正式验收**。依据：[实施计划](../guides/M4_运行可靠性实施计划.md)、[运行契约v1](../guides/M4_运行契约_v1.md)、[M4.6交接](M4_6_重启政策与必要兼容.md)。机器记录见[实施证据](../reports/M4_7_实施证据_2026-10-27.json)。

## 1. 已实现的入口与备份单元

新增`python -m backend.backup`，提供create、verify、restore三个本地命令。备份是目录格式，restore只创建新候选，不设置环境变量、不改现有应用配置、不启动任务或模型。

一个单元显式声明一个actual根及所有要保留的任务目录。Web/CLI若共用同一目录，只声明一次；若使用不同actual根，分别建立单元。工具扫描actual中的全部context，以及任务、固定输入和E/C载荷中的context，不以当前页面球员筛选。引用的context不在声明actual根中会拒绝，而不是生成缺事实的“完整恢复”。

示例spec文件如下，路径需换成已停写的单元；本轮实验全部使用隔离副本：

```json
{
  "schema_version": 1,
  "actual_root": "C:/career/actual",
  "tasks": {"web": "C:/career/web-tasks", "cli": "C:/career/cli-tasks"},
  "settings": {"MODEL_NAME": "使用的模型名称"}
}
```

可选字段：

| 字段 | 含义 |
| --- | --- |
| native_datasets | 额外原生来源目录列表；已导入观察中的目录自动发现，只有binding还没有观察时需显式列出来源 |
| source_map | 对已有恢复单元再次备份时使用其source-map.json；保留原逻辑来源路径 |
| file_sources | 非原生game_observation的raw_reference字符串到本地证据文件的显式映射；缺证据不声称完整 |
| assets | 标签到附加文件/目录的映射，例如knowledge原文；归档保留字节和摘要，不自动改RAG运行路径 |
| legacy_metadata | 标签到旧CLI JSON列表索引的映射；只保留元数据，不伪造可恢复Mission |
| settings | 允许的非秘密模型/RAG/会话参数及FAIT_RUNTIME_*预算覆盖；工具同时记录当前非秘密默认值和预算 |

MODEL_NAME、embedding/rerank标识、相关RAG/会话参数和运行预算进入清单；密钥键、未知配置键、无效预算拒绝，`.env`不打包。清单记录外部知识/模型目录及依赖版本；代码、密钥和未声明的外部资源另行提供。可用assets保存知识原文或其他必要资料；模型缓存和索引可按对应环境重建，不把它们冒充已随归档提供。

```powershell
.\venv\Scripts\python.exe -m backend.backup create --spec C:/career/backup-spec.json --output C:/career-backups/backup-001
.\venv\Scripts\python.exe -m backend.backup verify C:/career-backups/backup-001
.\venv\Scripts\python.exe -m backend.backup restore C:/career-backups/backup-001 --output C:/career-restore/candidate-001
```

命令成功退出0，失败输出REFUSED并退出非零。输出必须全新且不与actual、任务或来源重叠；不会覆盖既有目录。备份/恢复中途失败的候选可保留供检查，没有有效完成标记，重试使用另一新目录。

## 2. 停写、SQLite与预检

操作前停止所有受控写者。工具按固定顺序取得所有声明任务目录的`.writer.lock`、所有checkpoint写锁，再取得actual根写锁；持有到备份验证与READY写出后才释放。占用时快速拒绝，不终止其他进程、不删锁文件，不提供在线热备。受信写者必须使用当前锁协议；旧程序须先停止。

每个任务根归档workspace.sqlite3及存在的checkpoints.sqlite3。使用SQLite backup API读取已提交视图，包含WAL中尚未checkpoint的提交，输出独立数据库；不把活跃的两个库分别进行普通文件复制。SQLite备份阶段有30秒等待预算。actual聚合、绑定和collector回执按原字节复制；运行锁、临时文件和任务runs诊断材料不作为恢复权威输入。

清单包括所有归档文件SHA256、context/状态版本/快照身份、任务终态、暂停位置、固定输入摘要、报告摘要、全库表数量、原生绑定/回执与来源、代码revision和源码摘要、关键checkpoint依赖版本及非秘密配置。没有新建业务表或改变数据库格式。

code_revision记录备份时的HEAD，code_sha256覆盖清单列明的运行目录；数据归档不包含完整源码或未提交修改，须另外保留相符代码。本轮在当前Windows/已安装依赖组合验证，不据此推广到其他平台或全部历史发布版本。

预检复用M4.6只读数据库布局、integrity_check/foreign_key_check、固定输入和暂停校验，并核对：

- A聚合路径/context、state_version/snapshot_id、观察语义摘要及索引。
- 每个Mission原固定A、记忆、反馈及公开引用；暂停时的operation归属/类型/状态/pause与checkpoint一致。
- 已交付报告仍匹配当前有效成果、正文和固定材料；依赖报告/建议的checkpoint不能缺失。
- E/C载荷中的context存在，全部业务表和数据随workspace页快照保留；不从聊天重建E/C。
- 原生来源按审阅包重新解析，历史path/sha256与binding基线可达且一致；非原生来源需显式文件映射。

verify是只读检查，不构造MissionService、不运行图节点、不补建表、不重新投影或调用模型。它校验文件清单与完成摘要；缺文件、多出文件、格式/依赖不兼容或内容不一致均拒绝。清单用于完整性复核，不是第三方归档的签名认证或任意旧版迁移器。

## 3. 原生来源迁移与身份保持

原生观察的raw_reference包含旧dataset绝对路径，该字符串参与语义摘要。工具不改它、不重写state_version、观察身份或历史输入，而把完整来源目录归档到`sources/real_test/<稳定标签>/`。

restore生成独立的source-map.json，记录原逻辑路径、候选内相对路径及完整目录摘要。Collector新增可选`--source-map`或`FAIT_NATIVE_SOURCE_MAP`：先核对映射和目录摘要，在新物理目录解析包，生成观察时仍用原逻辑路径。因此原采集批次重放命中原DUPLICATE，而不会因换盘/换用户目录生成新观察或内容冲突。

```powershell
# 使用候选的实际路径；dataset参数可用清单中的原逻辑路径或候选物理路径。
.\venv\Scripts\python.exe -m game_adapters.pes2021_import preview C:/old-location/approved-package --actual-root C:/career-restore/candidate-001/actual --source-map C:/career-restore/candidate-001/source-map.json
```

映射启用时未登记或不唯一的来源拒绝，不悄悄回落原目录。恢复单元再次备份可以传同一个source_map，继续保存原逻辑身份和证据。映射中的历史来源保持不可变；后续新增采集仍走D的显式审阅/来源配置流程，不是自动适配任意新游戏目录。

## 4. 候选状态与手动切换

备份通过后有manifest.json和READY.json，READY绑定清单摘要。restore先验证归档，再向新目录复制；复制后再次核对全文件摘要、任务/A/E/C与来源，才生成：

- RESTORE_READY.json：记录已验证inventory及activated=false。
- source-map.json：来源迁移映射。
- restored-config.json：候选actual、所有任务根、context列表、资料目录和非秘密参数。

复制后校验失败生成RESTORE_FAILED.json，不生成RESTORE_READY。恢复目标不能是原actual/任务/原生来源的子目录，也不能是既有候选。归档保持不变；再次恢复到另一新目录得到相同初始记录，输入/创建回执仍保留原防重身份。

切换时先确认RESTORE_READY，保持旧服务停止，从restored-config选择明确的任务根与context，手动设置FAIT_PLAYER_DATA_MODE=actual、FAIT_PLAYER_DATA_ROOT、FAIT_DATA_DIR或FAIT_CLI_DATA_DIR、FAIT_CAREER_ID/BRANCH_ID/PLAYER_ID，以及FAIT_NATIVE_SOURCE_MAP；模型密钥单独配置。附加资料的运行路径由操作者按对应环境配置。工具不替用户启动、激活或覆盖旧工作区。

首次正常启动沿用M4.6：暂停按原材料恢复，运行中断明确失败且不重放，已完成报告与取消终态保留；E投影仍按原身份幂等。RESTORE_READY表示候选初始数据通过预检，不是后续写入后的永久一致性证书，也不表示已认证模型联网或报告专业质量。

## 6. 后续边界

本项支持当前actual单元、已知workspace/checkpoint及原生包格式；demo任务、只有旧CLI元数据的目录、任意外部旧版本和在线热备不作恢复承诺。源码/关键依赖及外部资源须按清单准备；未自动打包未声明目录、云端凭据或整个游戏安装目录。

原有memory用户修改、M3实际/任务/原生来源保持原字节；测试只在新的m4-implementation目录写入。没有切换现有应用、操作游戏、调用付费模型或提交/推送代码。
