## 1. 交付行为

首次任务、报告解释、补信息和报告审批都有持久请求回执。相同身份、相同内容返回原message/mission/operation，不重读最新A、不重新冻结输入、不重复入队或调用模型；合法请求中同ID异内容或跨任务入口复用身份返回409。真正的新请求仍允许使用相同问题文本。

每个具体暂停生成`pause_id`；输入同时提交request与pause身份。原请求重放返回旧回执，旧表单换一个request_id也不能作用于后来同字段的新暂停。

沿用原有创建事务，在workspace增加`request_receipts`与`operations`两张表；没有引入重试框架或替换图/Agent。原continuation、E行动/比较与C记忆的防重规则保留，E/C自己的请求命名空间继续使用原表。

## 2. API

| 接口 | 请求变化 | 回执/拒绝 |
| --- | --- | --- |
| POST /api/messages | 必填request_id；解释仍用原mission_id；文本补信息还需pause_id | 原message_id/mission_id，加operation_id、accepted、replayed |
| POST /api/missions/{id}/input | 必填request_id、pause_id，保留values | 与消息接口相同的回执；旧pause身份409，非法字段/值422 |
| GET /api/missions/{id}/operations | 新增只读列表 | 工作流和独立解释各自的身份、状态、run、暂停与中断原因 |
| POST /api/mission-continuations | 原请求不变 | 加operation_id/replayed；旧请求继续按原hash与原回执读取 |

不提供身份的旧写客户端返回422，不在服务端自动生成新ID绕过防重。已接受的重放也会先通过请求格式解析；业务回执查找优先于运行/终态及最新输入检查。

```json
{
  "request_id": "client-create-001",
  "conversation_id": "conversation-one",
  "content": "根据档案解释训练安排",
  "intent": "new_mission"
}
```

```json
{
  "request_id": "client-input-001",
  "pause_id": "从当前Mission.blocked.pause_id读取",
  "values": {"approved": true}
}
```

请求回执、消息、事件、operation和相应Mission/固定输入在各自一次接收事务中落库；入队仍在事务之后。事务失败不留下已接收回执；落库后未执行就退出，启动时标明中断，不自动重放。

## 3. 操作和暂停

新工作流有独立`workflow_operation_id`；暂停恢复沿用operation、递增run。每次解释创建新的operation，原报告生成任务不被改成运行中。原报告的结论、输入和生成计量不会因为解释而重写；完整计量仍待M4.5。

当前executor正常执行时更新QUEUED/RUNNING/PAUSED/COMPLETED/FAILED。服务启动将遗留QUEUED/RUNNING操作记为FAILED/INTERRUPTED；完成Mission上的解释中断只影响解释，原报告继续可读。相同request重放不会重新执行这个失败操作。

旧BLOCKED记录读取时提供基于Mission身份及sequence的稳定legacy pause标识，不把GET变成数据迁移。显式续跑校验通过后，事务建立`legacy_history=true`的工作流operation；原固定输入和checkpoint不改写，不伪造旧执行用量。

取消、时限、有限队列、统一最终发布事务和进程监督尚未接入；当前服务仍使用原线程executor。不要把本项的operation记录当成M4.3/M4.4已经完成。

## 4. Web与CLI

Web在请求发出前把完整待确认请求写入localStorage。丢响应后刷新恢复同一草稿conversation、内容和request_id；编辑内容换新ID。收到成功回执才清除对应待确认项。明确新建任务会创建新草稿conversation，不把新意图误当旧重试。

暂停表单缓存按Mission+pause身份隔离，组件也以pause身份切换；即使刷新前后都是同一个字段名，新暂停也不会自动带入旧答案或旧请求ID。

```powershell
# 同一创建请求重试必须保持相同内容和身份；自动生成的身份会在提交前打印并刷新输出。
.\venv\Scripts\python.exe app.py "训练安排" --request-id cli-create-001
.\venv\Scripts\python.exe app.py --explain <mission_id> "解释原报告依据" --request-id cli-explain-001
.\venv\Scripts\python.exe app.py --continue <mission_id> --request-id cli-input-001
```

CLI首次创建使用由请求身份确定的conversation，跨进程重试不因随机conversation变成内容冲突。已有回执不需要模型配置、最新A或新runtime；不会隐式恢复下一暂停。`--continue --request-id`若已被该Mission接收，查询并展示原回执/现状态；新的暂停回答使用新的request_id。

新增`--explain`沿用Web相同入口。解释失败返回非零退出码，原Mission仍完成；相同ID重放不会重调用模型，重新提问需新身份。`--list`/`--show`继续只读，不初始化新表。

## 5. 格式与部署

workspace核心格式采用SQLite `user_version=1`。版本0首次由服务在一个事务中增表并设置版本，不重写旧任务、固定输入或checkpoint；版本1重复启动不再次写版本号。未来未知版本在WAL/DDL写入前拒绝；只读历史不会启动Store或执行升级。

本轮只在新隔离目录执行升级/旧格式续跑测试。发布到已有工作区前，先停止旧服务和所有写者，保存actual、任务库/checkpoint及WAL、collector材料、原始来源和非秘密配置的一致副本，再在候选副本启动检查。不能把回退代码当作回退数据；本轮没有替用户升级实际工作区或重启服务。
