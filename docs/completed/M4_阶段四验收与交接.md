## 4. 复现方式

在当前Windows依赖环境、仓库根目录执行，输出使用全新目录：

```powershell
$env:PYTHONUTF8='1'
.\venv\Scripts\python.exe -m evaluation.run_m48 --root local_data/game_imports/m4-implementation/<新验收目录>
node evaluation/m45_frontend.mjs local_data/game_imports/m4-implementation/<新前端目录>
```

第二条命令默认只运行24项已选受控浏览器场景及14项单元；不是完整50项。生产构建在`frontend/`执行`npm.cmd run build`。完整50项另需隔离真实demo API，不能将API连接缺失误记为产品回归。

完整浏览器、collector35项、共享读者和终态备份的补充脚本原文已嵌入正式JSON的`supplemental_reproduction_sources`，并有摘要。恢复脚本到新的本地验收材料目录，将其中固定的`20261027-m48-acceptance-01`替换为新run名；从仓库根使用`Get-Content -Raw <脚本路径> | .\venv\Scripts\python.exe -`执行。`run_adapter_gate.py`、`replay_shared_readers.py`还需在`-`后传`--root <新隔离目录>`。完整浏览器使用19585/19586端口，重复运行同样选新目录；不连接游戏或外部模型。

核心原生来源验收需要本机保留的M3受审阅原件（原actual/任务与192份原生文件），不随Git分发；缺失不能用合成材料冒充。公开仓库本身不包含这些原件。API/SQLite/checkpoint/进程均为真实组件，图和模型内容按各场景使用确定性替身。

## 5. 运行、部署与回撤

正式验收不等于已切换现有实际工作区。本轮没有启动用户实际服务、升级原任务库、变更球员数据根或操作游戏。

部署当前版本时先正常停止旧服务和collector，等待执行清理；旧代码未必遵守新锁。按[M4.7交接](M4_7_停写备份与新目录恢复.md)声明完整actual、Web/CLI任务根及来源，依次create、verify、restore到独立新候选。工具不猜测未声明的库，不终止其他进程，不覆盖原数据。

通过RESTORE_READY仍为`activated=false`。使用对应代码和关键依赖、另配密钥/模型/知识资料，明确选择context及Web/CLI任务根后，再手动切换配置。`health=ok`只表示服务健康，不是整单元恢复合格或专业质量证明。当前默认预算、取消清理查询与拒绝处理见运行契约和排障指南。

执行中断按operation明确失败，使用新的关联retry；原request重放只取原结果。两暂停经核验恢复原输入；取消不可恢复；失败解释保留原报告。用量未知保留null和已知部分，HTTP尝试计数不是提供方账单。

回撤使用匹配旧代码的完整升级前数据副本；不能仅撤回代码、删除新状态/记录或混用两代写者。保留当前候选与原件，不以删除checkpoint或锁文件完成降级。
