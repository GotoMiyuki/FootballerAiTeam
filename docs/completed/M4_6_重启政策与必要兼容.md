## 1. 实现与边界

本项沿用operation/run、Windows Job、单执行槽、固定输入、两个暂停和原子发布门。没有更换Agent输出体系或增加自动续跑队列。B4保留旧Plan/Review/Hypothesis表达，仍以有效成果、当前审查及operation运行资格决定交付；只补齐恢复路径上可复现的不一致。

### 重启按操作处理

| 持久状态 | 启动后的处理 |
| --- | --- |
| 创建已提交未入队、QUEUED、RUNNING工作流 | 原operation FAILED/INTERRUPTED，原Mission失败并保留固定输入；不自动执行 |
| 已完成Mission上的QUEUED/RUNNING解释 | 只将解释标记FAILED/INTERRUPTED，追加可见失败消息及事件；原报告、生成telemetry和E/C保留 |
| 缺输入或报告审批PAUSED | 保留暂停；查看/恢复时核对操作、输入、checkpoint及固定引用，不读latest补齐 |
| COMPLETED/FAILED/CANCELLED | 保留终态及原因；CANCELLED不会改成FAILED |
| CANCELLED且清理PENDING | 在确认旧checkpoint写者已释放后，收口清理；缺失的末段计量仍为未知 |
| 旧任务无operation且仍在执行 | 沿用明确失败政策；旧完成历史不伪造operation或可恢复图 |

中断操作、相应Mission/解释失败消息和事件在同一workspace事务保存。故障回滚时不留下“操作仍排队但Mission已失败”的半个决定。第二次启动或原request重放不会重复失败消息、图执行或模型调用；继续工作使用新的关联任务。

暂停/完成事务可能先于协调者最后一次计量结算提交。若启动时发现这些操作仍有run_started_at/queued_at，保留业务终态、清除失效的实时执行时钟，标记timing/budget历史不完整，保留已结算下界，不用离线时间补造执行耗时。已取得并有完整末帧的响应计量仍可保留；缺失的时间不因业务完成就变成已知。暂停继续沿用已有旧预算历史兼容策略：后续执行按保留累计值取得有限预算，不承诺未结算崩溃段的完整总量。

### checkpoint写者隔离

任务目录原`.writer.lock`继续约束协调者。新增同目录`.checkpoint-writer.lock`约束实际图worker，从构造图到关闭checkpoint连接一直持有。服务启动在打开workspace之前，用cleanup_seconds预算等待这把OS锁释放；超时明确拒绝，不改业务数据库，不按PID或进程名终止其他进程。新worker也必须取得同一锁才能写checkpoint。

Windows Job仍负责拥有者异常退出时清理所属进程树，文件锁由OS随进程退出释放。锁是实际写入互斥，启动门不是任意旧版本进程的接管器；发布前必须停止没有使用该锁的旧程序。不能删除锁文件解锁。解释不写checkpoint，不占这把图写锁；其生命周期仍由私有Job管理。

### 恢复接收前核验固定材料

暂停任务若已有workflow_operation_id，操作必须属于同Mission、类型为workflow、状态PAUSED且pause_id一致。原Mission残留BLOCKED不能替已失败操作授权恢复，界面的可用操作也据此收敛。

接收补信息/审批前，读取并核验原mission_inputs的schema_version、mode、content_hash、球员快照和公开版本引用。之后将checkpoint中的完整player_snapshot、continuation_context、career_memory_context及原始请求目标与持久输入比对；C记忆/E反馈仍执行其原有内容摘要、context、版本及公开引用核验。校验失败不保存新回执、消息或run，也不启动模型。

这修复了仅凭相同context/state_version/snapshot_id就接受内容不同的球员快照、或未完整核对选定历史的路径。执行端恢复继续比对同一输入，所有材料来自提交时冻结的集合。actual最新状态、C更正和E后来记录均不用于替换原输入。

## 2. 支持的格式

| 数据 | 支持范围 | 拒绝与数据影响 |
| --- | --- | --- |
| workspace.sqlite3 | user_version=1的当前核心表；user_version=0的已知旧核心布局，可增量建立operations/request_receipts后升到1 | 写前核对核心表和列；未知版本、未知非空布局或缺失必需列拒绝，不能靠CREATE IF NOT EXISTS补成空历史 |
| mission_inputs | schema_version=1、相符的live/demo模式、正确content_hash；live球员引用须与公开Mission一致 | 缺失、非法结构、错hash/版本/模式/context均在接收恢复前拒绝 |
| checkpoints.sqlite3 | 当前SqliteSaver表结构，SQLite user_version=0；图执行器实际落盘checkpoint内容v=4 | 只读检查结构和目标checkpoint内容版本；未来版本不自动迁移、不删除、不重建暂停 |
| operation及计量 | 当前DTO，缺省字段保持M4.2/M4.5的旧记录读法，metering.version=1 | 旧计量缺口仍未知；不虚构历史调用、时间或取消目标 |
| 旧CLI sessions.json | 只读元数据索引 | 不导入成完整Mission，不提供续跑；只读SQL索引也先核对任务库格式 |

SQLite扩展业务表和各领域对象继续沿用E/C等现有契约；本项不是任意外部历史发布版本的通用迁移器。表布局检查不替代M4.7整套备份的完整性、来源和路径预检。当前依赖组合是验证对象，不据包基础接口中的旧常量推断图实际写入版本。

本项不增加SQLite表或改变user_version，不重写既有checkpoint。新写锁文件是运行期协调材料。撤回前停止当前协调者/worker并保留完整副本；旧代码不使用新锁，也不保证保留新增操作元数据，不能混合运行。
