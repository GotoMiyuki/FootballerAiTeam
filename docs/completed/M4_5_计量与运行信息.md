## 1. 交付行为

Web/CLI沿用同一个operation/run和受监督执行器。新增持久操作计量，分别记录模型逻辑调用、SDK实际发起的HTTP尝试、工具调用、调用结果与响应usage。报告生成跨暂停沿用工作流operation；每次解释建立独立operation。原Mission.telemetry继续表示生成报告时的图节点记录，后续解释不重写它；另提供各操作及累计观察视图。

模型和工具经过现有调用封装。逻辑调用使用span身份；SDK同步HTTP客户端的request/response钩子记录每次发送及状态码，因此500后成功重试是1次逻辑调用、2次HTTP尝试。SDK退避仍计入原逻辑调用和执行预算，不生成新request/run。Manager修订、重规划和各角色使用同一封装；原图计量继续记录修订/重规划次数。

执行子进程只回传计量元数据：span、种类、角色/用途、尝试序号、状态、耗时和usage数值，不回传URL、密钥、提示或响应正文。协调者按operation/run核对并持久保存；重复元数据不会叠加。正常done/error帧给出有序执行记录的收口；强制中止或崩溃缺少末帧时保留已观测部分并标记缺口。取消后的收尾元数据只补观察，不恢复业务发布资格。

## 2. 未知、已知部分与零

| 情况 | 展示与持久语义 |
| --- | --- |
| 同一次成功HTTP响应完整提供usage | 对应输入/输出为已知值；执行记录完整时可给出完整总量 |
| 响应缺usage或只给出一侧 | 缺失侧为null；保留取得的已知部分，不补0 |
| 500后重试成功，最后响应11/7 | 逻辑调用1、HTTP尝试2；已知响应合计11/7，失败尝试用量未知，完整总量null |
| 两次失败或400直接失败 | 尝试次数照实；未取得usage为未知 |
| 模型发送后超时/取消 | 已发起尝试仍保留；未返回的usage未知，逻辑调用标记中断 |
| 排队中取消，从未派发 | 有确认的未执行记录，模型/工具及token可知为0 |
| 提供方明确返回usage=0 | 已知零，与未提供usage区分 |
| 旧operation没有metering，或进程崩溃缺尾段 | 完整计数/用量未知；已有观察保留，不用历史默认0证明零消耗 |

`known_input_tokens/known_output_tokens`只合计取得的响应部分，不能作为提供方账单。`usage_known_calls`显示取得两侧usage的逻辑响应数；`unknown_attempts`另说明失败/中断尝试，避免一次逻辑调用已有成功usage就掩盖其重试缺口。`counts_complete`说明执行观察记录是否收口；完整HTTP次数还要求客户端尝试可观测，完整token还要求各调用成功、usage齐全且没有未取得usage的错误尝试。

图节点telemetry的响应合计与操作HTTP覆盖范围不同。新图记录增加usage_tracking_version、已知响应合计和未知响应数；缺覆盖标记的旧图计量继续保留历史语义，合并或显示时不把旧默认0认定为已知。图events仍最多200条；持久操作计量不从这个截断数组反算，也不因图重置重复计数。

## 3. 时间分账

| 项目 | 范围 |
| --- | --- |
| 排队 | 已接受到本执行段开始；包含排队取消/过期前的等待 |
| 实际执行 | 各执行段累计，包含构造运行时、执行及协调收尾；使用单调钟结算和扣预算 |
| 用户等待 | 缺输入/报告审批发布到用户有效恢复或取消；跨重启保留，不扣执行预算 |
| 总体墙钟 | operation创建到完成收尾；独立解释各自计时 |
| 节点耗时累计 | 原图节点latency_ms之和，单独标注，不当作任务墙钟 |

UTC时间点支持查询时的实时展示；正在排队、执行或等待时，读取同一revision也会随read_at推进。执行段结束后的持久累计仍由单调钟结算。系统时钟调整会影响UTC展示；它不改变单调钟执行预算。旧历史或崩溃未结算段的完整分类时间为null，并保留已知下界。重放已接收输入不重复累计等待。

业务暂停/完成提交可能早于协调者最后一次计量结算。需要判断冻结预算的验证器等待执行句柄收尾；客户端用最终operation.updated刷新计量。原报告发布事务与取消先后规则继续由M4.4持有，计量结算不重新参与成果终态竞争。

## 4. API、Web和CLI

```text
GET /api/missions/{mission_id}/runtime
```

只读返回mission_id、mission_sequence、read_at、workflow_operation_id、operations、totals和report_telemetry。每个operation附usage和timing；聚合是快照，客户端替换而非累加。查询不调用模型、不增加revision、不写库。缺失Mission仍返回404。

operation.revision在每次真实保存后递增，旧记录默认0。前端结合Mission sequence、operation revision/run和read_at拒绝迟到快照；不同Mission使用独立查询缓存。原SSE事件sequence和重放方式保留，操作收尾发送operation.updated触发刷新；SSE重放不进入计量写入口。同revision的较新read_at允许等待时钟前进，较旧HTTP返回不能让终态、操作列表或计数退回。

Web的“任务运行信息”分别展示生成、每次解释与累计观察，显示完整用量未知和已知部分；操作错误区分原请求重放、解释新提问和关联新任务。取消仍使用M4.4明确目标。CLI只读show增加调用/尝试、覆盖范围及四类时间，原节点输出改标“节点耗时累计”，缺usage显示未知。

运行日志关联mission/request/operation/run，失败记录原因或异常类名；不记录完整提示、密钥和提供方原始错误正文。范围是本应用的运行日志和新计量元数据，不承诺第三方SDK调试日志或既有业务材料全部经过统一脱敏。
